# Simulator interface

Local operational tool for developers and demonstration operators. Product facts are in PRODUCT.md. User selected a local browser control panel; no brand assets were supplied.

Use a slider as the main weight control, with a default single-bin selection and quick Empty, 25%, 50%, 85% and Full presets. The main flow is choose a bin, preview a draft and Send reading. This one action applies a manual weight and publishes it once. Exact entry, slider overload range, automatic scenarios, connection settings and fleet replacement stay in labelled native disclosure sections. Keep 100-bin operation practical through percentage-based bulk changes and warehouse filtering. Keep local simulator state distinct from broker acknowledgement and eventual Ditto updates.

An on-page operating guide defines variables, action scope and whether a control sends a message. Preserve kilograms as the payload unit and clearly label percentage as a calculation against weight capacity. The user chose explicit sending: dragging or releasing the slider only previews; Send reading applies and publishes. Slider previews must not be overwritten by streaming state updates.

The static design detector reports cramped section padding for the Tailwind-padded panels. Rendered computed styles confirm 16 px on the connection panel and 24 px on the controller, fleet and guide panels; retain those intentional insets rather than adding duplicate padding.

Light neutral work surface for an indoor experience-center screen, dark header, semantic status colors, daisyUI controls, locally built CSS. In Your bins, one measured weight bar per row visualizes simulator capacity with a textual percentage. Its fixed 85% highlight is a local display convention; dashboard alerts are derived on read from each bin's raw received weight, imported model capacity and configured threshold. Percentage and alert state are not telemetry fields stored in Ditto. No decorative imagery, custom icon system, animation, or external font/network dependency. Accessible labels, keyboard focus and responsive stacking are required.

View the digital twins is a full-width handoff section below the controller and fleet, reached from the header's Ditto results link. Its Open warehouse dashboard action opens the separate dashboard at port 4321. Preserve the simulator's existing panel, button and supporting-text styles. The simulator no longer contains a Received by Ditto table or a /api/twins readback flow. Received measurements, model-based statuses, warehouse filters and bin details belong to the dashboard; its surface patterns are recorded in ../dashboard/DESIGN.md.

Keep an unsent slider draft, applied simulator values, MQTT acknowledgement and dashboard readback distinct in labels and feedback. The simulator sends to the external local broker; Ditto's native MQTT connection updates the twin without a separate relay. An MQTT acknowledgement confirms broker receipt only. The independent dashboard derives percentages and statuses from the current model on each read, so model changes do not require another reading. Its receipt time describes the last received weight, not whether a paused or silent bin is currently online.

Simulator Automatic scenarios remain sending controls for the local fleet. The dashboard's separate Scenario lab uses the inherited visual system for saved drafts and read-only projections; it clearly labels preview output and leaves live execution and scheduling for later integration.
